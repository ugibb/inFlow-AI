4. 权限边界：**持码游客即可读**——后端新增游客只读通道（UUID 即阅读凭证），扫码者无需登录、无需是文章所有者。

## 一、现状梳理（关键事实）

1. **前端只是展示壳**：`03-src/frontend/components/deep-read-panel.tsx` 渲染的是 `articles.deep_read_html`（worker 直写库）；点「截图」下载的 PNG 也是 worker 预渲染回传的——`backend/routers/articles.py` 的 screenshot 端点只按 job 回读 `03_display/{job_id}.png`，前端传的 html 已被忽略（兼容旧契约）。
   → **本仓库（inFlow-ai）前端/后端都不用改**，真正要动的是 worker 仓库（本地 `inflow-local`，git remote 为 `ugibb/inflow-worker`）。
2. **HTML 由 LLM 按 Prompt 生成**：区块9 页脚规格在 worker 的 `05-src/skills/_shared/render/prompts/s4/20250413-播客访谈记录生成网页Prompt.md`（区块 9：页脚，必须输出）。二维码不能让 LLM 自己画（必然画成假码），必须**程序化注入**。
3. **一注入点覆盖三产物**：`render_card_png_for_job` 中 LLM 出 HTML 后、写盘截图前注入，同一份 HTML 覆盖：HTML 落盘（`{job_id}.html`）→ PNG 截图（Playwright）→ `deep_read_html` 写库（executor `_persist_final_assets_to_article` 读的就是这个文件）。
4. **微信凭据已就绪**：云端后端已有 `WECHAT_APPID / WECHAT_SECRET`（微信一键登录在用），appid `wxe091ce737f45cacc` 与 `miniprogram/project.config.json` 一致。worker 侧只需把同值加进 `.env.local-worker`。

## 二、技术选型

### 码类型：微信官方小程序码（`wxa/getwxacodeunlimit`）

- 微信内**长按识别 / 相机扫码**都能直达小程序指定页，是唯一不依赖「已备案域名 + 扫普通链接二维码打开小程序」控制台配置的稳妥路径。
- 数量不限（区别于 `wxacode.get` 的 10 万个总量上限），适合按文章一码。

### scene 传参：UUID 去横线

- 文章 id 为 36 位 UUID（含 4 个横线），超过 scene 的 32 字符上限；**去掉横线恰好 32 位 hex**，正好卡在限制内。
- 无需给 articles 加短 id 列、无需 base62 编解码。
- 小程序 read 页 `onLoad` 补 `options.scene` 解析（decodeURIComponent → 32 位 hex → 还原带横线 UUID），登录闭环复用现有 redirect 逻辑（`pages/read/read.ts` 已支持无 token 走登录重定向）。
- scene 字符集仅支持数字/大小写英文及 `!#$&'()*+,/:;=?@-._`——hex（0-9a-f）全部合法。

### 页脚布局（区块9 品牌区左侧，内联样式自适应明暗主题）

```
┌────────────────────────────────────────────────┐
│ 来源：小宇宙            ┌────┐  inFlow AI       │
│ 主播 · 嘉宾 · EP 69     │ ▓▓ │  内容精华提炼     │
│                        └────┘                  │
│                  微信扫码 · 小程序读全文          │
└────────────────────────────────────────────────┘
```

- 二维码块自带白色底 + 圆角 + padding（小程序码本身白底，深色主题下也清晰）。
- 品牌区文字（inFlow AI / 内容精华提炼）保持现状，码放其左侧。

## 八、二维码版本切换：trial（体验版联调）↔ release（线上正式版）

页脚小程序码指向哪个小程序版本，由 worker `.env.local-worker` 的环境变量 **`WXACODE_ENV_VERSION`** 控制：

| 值 | 指向 | 谁能打开 | 何时用 |
|---|---|---|---|
| `release`（**默认**，即删除该行/不配置） | 线上正式版 | 所有用户 | 日常生成、**正式发布后必须保持** |
| `trial` | 体验版 | 仅后台「体验成员」微信号 | 发版前真机联调（验证 scene/游客通道） |
| `develop` | 开发版 | 开发版成员（一般不用） | — |

### 切换步骤（4 步）

1. 编辑 `inflow-local/.env.local-worker`，设 `WXACODE_ENV_VERSION=trial`（联调用）或 `release`（**删掉该行即回默认**，勿留 trial）。
2. **删除该文章的码缓存** `04-output/_wxacode/{文章UUID去横线}.png`（可整目录清空）。码按文章**永久缓存**（一篇一码），**不删则命中旧缓存、切了也还是旧版本码**。
3. 重启 worker：`.\start-worker.ps1 -Stop` 后 `.\start-worker.ps1 -Detach`。
4. 重新触发该文卡片合成（新文章走一次 compose 即带新码）。码在**合成时注入**——已生成的 PNG / HTML / 库内 `deep_read_html` 不会自动更新，存量卡片要换码只能重跑该文 compose。

### 已知差异与坑（2026-09-08 联调实测）

- **微信内「长按识别」只拉起线上正式版，不认体验版码**；体验码只能用「扫一扫」进。所以 trial 期发现「扫码能进体验版、长按却空白」是微信机制、非 bug，空白页=落到了旧线上版。正式发布后 release 码长按/扫码一致，此现象消失。
- **第三方扫码器 / 相机解微信小程序码只会得到 `http://lp…` 乱码**（乱码尾部恰为 scene hex），属正常，勿据此判断码坏。
- **发版红线**：trial 码留在线上会令真实用户打不开——提审通过、正式发布后**务必切回 release 并重启**。
- 生效范围仅限「之后合成」的卡片；trial 期生成的存量卡片若需对外，须重跑 compose。

> 状态（2026-09-09）：小程序审核通过。worker 已切回 `release`（`.env.local-worker` 无 `WXACODE_ENV_VERSION` 行，重启生效），trial 期码缓存已全部清除。
