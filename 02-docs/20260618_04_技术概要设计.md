### 1.2 技术栈

| 层级 | 技术选型 | 版本 | 选型理由 |
|---|---|---|---|
| 前端框架 | Next.js | 14 | App Router + SSR + 响应式优先 |
| 前端语言 | TypeScript | 5.x | 类型安全 |
| 前端样式 | Tailwind CSS | 3.x | 快速 UI 开发 |
| 富文本编辑 | MDXEditor | latest | WYSIWYG + Markdown 双模式 |
| 后端框架 | FastAPI | 0.11x | 原生 async、自动 OpenAPI |
| 后端语言 | Python | 3.10+ | AI 生态成熟 |
| ORM | SQLAlchemy | 2.x async | 类型安全、async 支持 |
| 数据验证 | Pydantic | v2 | 与 FastAPI 原生集成 |
| 关系数据库 | PostgreSQL | 16 | 稳定、pgvector 扩展成熟 |
| 向量存储 | pgvector | 0.7+ | 合并关系+向量，无需独立向量库 |
| 缓存 | Redis | 7 | Session / 任务队列 |
| 本地嵌入 | fastembed + ONNX | - | CPU 可运行，无 PyTorch 依赖 |
| 嵌入模型 | BAAI/bge-small-zh-v1.5 | - | 512 维，中文优化，95MB MIT |
| 网页抓取 | Playwright + curl_cffi + httpx | - | 绕过中文平台 TLS 指纹/JS 反爬 |
| 文件转换 | MarkItDown | - | Microsoft 出品，格式覆盖广 |
| 语音转录 | Whisper (local) + yt-dlp | - | 视频内容转文字 |
| 反向代理 | Nginx | latest | 单一入口，静态资源加速 |
| 容器化 | Docker Compose | v2 | 一键部署 |

### 1.3 部署架构

```
Docker Compose（4 个容器）:
  - nginx        → :80（生产入口）
  - frontend     → :3000
  - backend      → :8000
  - db           → PostgreSQL 16 + pgvector
  - redis        → :6379（可选）
```

## 三、核心业务流

### 3.1 文章入库主流程

```
用户操作（粘贴 URL）
      │
      ▼
POST /api/articles
      │
      ├─ URL 规范化（从分享文本中提取有效 URL）
      ├─ 去重检查（user_id + url 唯一索引）
      │
      ▼
parser_service.fetch_content(url)
      │
      ├─ 平台检测（detect_platform）
      ├─ 针对性抓取
      │   ├── 微信/头条/掘金  → Playwright headless
      │   ├── 小红书          → curl_cffi（TLS 指纹绕过）
      │   ├── B站/抖音        → 标记 ASR_PENDING，后台处理
      │   └── 通用网页        → httpx + BeautifulSoup
      ├─ HTML → Markdown 清洗
      └─ 返回：title, raw_content, cover_image, author
      │
      ▼
Article 写入数据库（status: fetch_status='completed'）
      │
      ▼（后台异步任务：BackgroundTasks）
      │
      ├─ AI 处理（ai_service.parse_article）
      │   ├── LLM 提取：标题/5句摘要/3-5关键点/标签/作者/平台
      │   └── JSON 解析（含 json_repair 容错）
      │
      ├─ 向量嵌入（ai_service.get_embedding）
      │   ├── 输入：title + summary + plain_text[:2000]
      │   └── 本地 fastembed 或外部 API（512 维）
      │
      ├─ 知识图谱边生成（graph_service.generate_graph）
      │   ├── 找候选文章（tag/keyword 过滤，最多 20 篇）
      │   ├── LLM 判断关系（related/prerequisite/extends/contradicts）
      │   └── 批量写入 knowledge_edges（ON CONFLICT DO NOTHING）
      │
      └─ ASR 后台扫描（若含 ASR_PENDING 标记）
          ├── B站：提取 audio URL → transcription_service
          └── YouTube：yt-dlp 下载 MP3 → Whisper 转录
```

### 3.2 RAG 问答流程

```
用户输入问题
      │
      ▼
POST /assistant/ask
      │
      ├─ 向量化问题（embedding，query 模式）
      │
      ▼
pgvector 余弦距离检索
      │  SELECT * FROM articles
      │  ORDER BY embedding <=> query_vec
      │  LIMIT top_k（默认 8）
      │
      ▼
构建上下文
      │  每篇文章取前 15 段落（约 3000 字符）
      │
      ▼
LLM 调用（temperature=0.3）
      │  Prompt: 问题 + 知识片段 + 引用格式要求
      │
      ▼
返回：answer（Markdown）+ citations（文章 ID + 片段 + 相关度分）
```

### 3.3 Spark 创作流程

```
用户输入一句话灵感
      │
      ▼
POST /api/articles/spark
      │
      ├─ Step 1：AI 规划文章结构
      │   └── LLM 输出：5 个 section（intro/background/main/practice/summary）
      │
      ├─ Step 2：逐节生成内容
      │   └── 每节 LLM 生成：key_points + content（Markdown）
      │
      ├─ Step 3：拼接完整文章（Markdown）
      │
      └─ Step 4：保存为 Article
          ├── url = "spark://<sentence>-<timestamp>"
          ├── source_platform = "spark"
          └── 触发后台 AI 处理（tags/embedding）
```

### 3.4 知识图谱生成流程

```
新文章入库后（后台任务）
      │
      ▼
graph_service.generate_graph(article_id)
      │
      ├─ 获取候选文章
      │   ├── 同标签文章（tag overlap）
      │   ├── 同关键词文章（plain_text ILIKE）
      │   └── 最多取 20 篇
      │
      ├─ LLM 分析关系
      │   ├── 输入：新文章 + 候选文章 摘要列表
      │   └── 输出：edges（source, target, relation_type, weight, desc）
      │
      └─ 写入 knowledge_edges
          └── ON CONFLICT DO NOTHING（幂等）
```

### 3.5 定期回顾推送流程

```
Cron 扫描（60s 间隔）
      │
      ▼
review_service.review_cron_loop()
      │
      ├─ 查询 next_send_at <= now() 的 ReviewSchedule
      │
      ├─ 对每个用户：
      │   ├── 查询近期入库文章（按 frequency_days 计算时间范围）
      │   ├── LLM 生成 Markdown 格式摘要文本
      │   └── 通过 WechatAccount 推送消息
      │
      └─ 更新 last_sent_at + 计算下次 next_send_at
```

### 3.6 Obsidian 同步流程

```
Obsidian 插件端（定时拉取）
      │
      ▼
GET /api/sync/articles?cursor=<cursor>&limit=200
      │  Header: Authorization: Bearer <sync_token>
      │
      ├─ Token 验证（检查 sync_token_version 是否匹配）
      ├─ 查询符合条件的文章（summary IS NOT NULL AND embedding IS NOT NULL）
      ├─ Keyset pagination（按 updated_at + id 排序）
      └─ 图片 URL 转绝对路径（X-Forwarded-Proto）
      │
      ▼
Obsidian 插件本地写入
      │
      ├─ 生成 Markdown frontmatter（tags/source/date 等）
      ├─ 写入 .md 文件（永不覆盖已有本地修改）
      └─ 更新 sync_state.json（已同步记录）
```

## 四、数据流

### 4.1 内容入库数据流

```
原始 URL / 文件 / 文本
         │
         ▼
    parser_service
    （平台感知抓取）
         │
         ▼
┌────────────────────────────────┐
│         Article（初始化）       │
│  raw_content  = HTML/Markdown  │
│  clean_content = Markdown      │
│  plain_text   = 纯文本          │
│  fetch_status = completed      │
│  embedding    = NULL           │
│  summary      = NULL           │
└────────────────────────────────┘
         │（后台异步）
         ▼
    ai_service.parse_article
         │
         ▼
┌────────────────────────────────┐
│         Article（AI 增强）      │
│  title        = AI 提取/修正   │
│  summary      = 5 句摘要        │
│  key_points   = [3-5 条]       │
│  tags         = [自动标签]      │
│  author       = 识别作者        │
│  reading_time = 估算分钟        │
└────────────────────────────────┘
         │
         ▼
    ai_service.get_embedding
         │
         ▼
┌────────────────────────────────┐
│         Article（向量化）       │
│  embedding = Vector(512)       │
└────────────────────────────────┘
         │
         ▼
    graph_service
         │
         ▼
┌────────────────────────────────┐
│      knowledge_edges           │
│  source_article_id             │
│  target_article_id             │
│  relation_type                 │
│  weight                        │
└────────────────────────────────┘
```

### 4.2 语义搜索数据流

```
用户输入查询词
       │
       ▼
ai_service.get_embedding(query, type="query")
       │
       ▼
pgvector SELECT ... ORDER BY embedding <=> $1 LIMIT k
       │
       ▼
按相关度排序结果列表
（relevance = max(0, 1 - cosine_distance)）
       │
       ▼
返回文章列表（含相关度分）
```

### 4.3 配置数据流

```
用户在 UI 配置 LLM（API Key / Model / Base URL）
       │
       ▼
POST /api/system/config
       │
       ▼
config_manager.update_config()
       │  写入 03-src/backend/app/config_store.json
       │
       ▼
ai_service 调用时读取：
  优先级：config_store.json > 环境变量 > 内置默认值
```

## 五、安全设计

### 5.1 认证机制

```
登录：username + password → bcrypt 验证 → 签发 JWT（24h）
普通 API：Bearer JWT → decode → 获取 user_id
同步 API：Bearer JWT（sync type）→ 验证 sync_token_version
微信绑定：临时 JWT session（5 分钟）
```

### 5.2 数据隔离

```
所有业务查询：WHERE user_id = current_user.id
超管查询：支持 ?username=xxx，通过 X-Act-As-User 代理
ORM 层强制过滤，防止越权
```

### 5.3 图片反代防 SSRF

```
请求 /api/images/proxy?url=xxx
       │
       ▼
白名单域名检查（mmbiz.qpic.cn / xhscdn.com / douyinpic.com 等）
       │ 不在白名单 → 403
       ▼
根据域名设置正确 Referer 头
       │
       ▼
httpx 代理请求 → 流式返回
```

## 六、后台任务

| 任务 | 触发方式 | 周期 | 说明 |
|---|---|---|---|
| AI 处理（摘要/标签/嵌入） | 文章入库后 BackgroundTask | 一次性 | FastAPI 内置，进程内 |
| 知识图谱边生成 | 文章入库后 BackgroundTask | 一次性 | 同上 |
| ASR 转录扫描 | 启动时创建 asyncio task | 每 30 秒 | 扫描 ASR_PENDING 标记 |
| 嵌入回填扫描 | 启动时创建 asyncio task | 每 5 分钟 | 扫描 embedding IS NULL |
| 定期回顾 Cron | 启动时创建 asyncio task | 每 60 秒 | 检查 next_send_at |

> ⚠️ **风险**：BackgroundTasks 在进程内运行，服务重启时会丢失未完成任务。`/api/articles/backfill-embeddings` 接口可手动触发补救。
