## 0. 本次改动内容

worker 端视频管线（youtube / douyin / bilibili 视频分区）落地后，read 页存在五类展示问题，本次全部修复：

| # | 问题 | 修复方式 |
|---|------|----------|
| 1 | 处理中显示音频布局、完成后显示图文布局（来回跳） | 云端 `_infer_content_type`：youtube/douyin 提交 URL 即判 `video`（bilibili 按 URL 路径分音/视频），read 页从创建起就是视频布局 |
| 2 | title 显示 URL 而非真实标题 | 两层：① stub 期 URL 标题不可避免（腾讯云出网访问不了 YouTube）；② **前端 job 轮询到终态立即静默刷新 article**——worker 直写库的真实标题自动呈现，无需手动刷新 |
| 3 | 无视频播放器 | 按已确认方案：**不回传 mp4**，头部视频卡（封面 + 平台/时长徽章 + 「去原平台观看」），站内不托管视频文件 |
| 4 | 【全文转录】tab 不显示 | tabs 门控从 `audio` 扩为 `audio || video`（静态逐句列表，无 seek） |
| 5 | 展示内容像图文页 | 视频专属布局：视频信息 tab（描述 + **截图画廊**，横向滚动点击放大）/ 章节速览（时间戳只读）/ AI精读 / 全文转录 / AI 解析 |

附带修复（定位过程中发现的隐患）：

- **PipelineBar 永远显示 8 步图文链**：外部 job 云端读不到 worker 本地 raw 文件，`get_job_status` 的 pipeline_steps 推断失败后无兜底 → 现回退到 `article.content_type`，视频任务正确显示 11 步视频链
- **单块重生成 / 顶部重新生成**：`_BLOCK_APPLICABLE`/`_BLOCK_WORKER_STEP`/`regenerate-ai` 全量纳入 video（转录块 worker 续跑复用 ASR；AI 块云端同步重解析）
- 新增接口：`GET /api/articles/{id}/screenshots`（序号列表）、`GET /api/articles/{id}/screenshots/{index}`（单张 PNG，前端 blob URL 过 Bearer 鉴权）

## 6. 风险与备注

- 截图画廊数据源是 worker 经 SFTP 回传的 `03_display/{job_id}_NNN.png`；老视频文章若无截图文件，
  画廊自动隐藏（接口返回空列表），不影响其余布局
- `_infer_content_type` 只影响**新提交**的 stub：存量已由 worker 修正过 `content_type` 的视频文章直接受益于展示层改动
- bilibili 视频分区靠 URL 路径识别（`/video/`、`BV…`、`b23.tv/BV…|av…`）；b23.tv 短链若不含 BV/av 特征
  会按音频推断，采集后 worker 仍会以 raw 为准修正（仅 stub 期布局短暂不准）
