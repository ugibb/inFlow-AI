## 0. 背景速览（改了什么、为什么）

### 0.1 问题一：自动刷新把页面顶回顶部

知识库页有两个后台轮询：采集任务轮询（3s）与 AI 处理轮询（4–5s）。原实现每次轮询都
`setLoading(true)`，整个文章网格被卸载换成骨架屏，滚动容器内容高度骤减，浏览器把滚动位置
clamp 回顶部——用户滚到页面中部时每几秒被顶回一次。

**修复**：`fetchArticles` 增加 `silent` 参数。轮询改为只拉**第 1 页**（按 `updated_at`
排序，新文章/刚处理完成的必在第 1 页）并**合并进列表头部**；深处已加载的卡片原样保留，
按 `article.id` 原地复用 DOM——新文章出现在顶部、处理中的卡在眼前补全，滚动位置纹丝不动。

### 0.2 问题二：瀑布流配传统分页条不搭

布局层是 CSS columns 瀑布流，数据层是每页 24 条的分页接口，UI 直接把页码条渲染出来，视觉割裂。

**修复**：删掉分页条，改为 `IntersectionObserver` 哨兵无限滚动——滚到底部前 600px 自动
追加下一页；底部显示加载 spinner /「已经到底啦」。配套调整：

| 配套改动 | 说明 |
| --- | --- |
| 哨兵 root 挂右栏滚动容器 | 页面滚动发生在该容器内而非 window，挂默认 root 永远不触发 |
| 批量删除/归档/移动改原地过滤 | 不再整表重拉，深滚位置不丢 |
| 搜索/筛选变化重置回第 1 页 | 显示骨架屏 + 回顶部（预期行为） |

## 4. 排障速查

| 服务器构建失败 | `docker compose up -d --build frontend` 前台跑看完整日志；npm 阶段 OOM 属偶发，重跑一次；确认 `git log` 拉到的就是 `30ac2ec` |

## 6. 已知边界（验收时不要误判为 bug）

1. **静默合并只拉第 1 页**：深处某张卡若被服务器排序（`updated_at`）挤出第 1 页，它的状态
   更新要等滚回顶部或重新进入页面才可见——影响极小（排序变动本身就意味着它已不在热点区）；
2. **无限滚动加载失败是静默的**（无 toast）：再滚一次即自动重试，与原分页失败行为一致；
3. **去重后卡片数可能略少于「已加载页数 × 24」**：历史重复 URL 在渲染层按 canonical URL
   去重（既有逻辑），「已经到底啦」出现的时机以 `total` 为准，略早于直觉属正常；
4. **文章总数 ≤ 24**（一页装得下）：不出现到底文案、也不触发加载，列表即全部内容。
