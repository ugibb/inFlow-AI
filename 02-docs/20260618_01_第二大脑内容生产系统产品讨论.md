## 第 3 轮

🤖 **AI**

这个项目从代码和 README 里，我读出来它实际上在同时解三层问题：

---

**第一层：采集问题**
中文互联网的内容高度碎片化，微信文章有防盗链、B站是视频、小红书反爬。这个项目用 Playwright + curl_cffi 绕过 TLS 指纹，把"任意中文内容"统一变成结构化文本存进数据库。

**第二层：理解问题**
光存进来没用。它在每篇内容入库后自动跑一条流水线：摘要 → 关键点 → 标签 → 向量嵌入 → 知识图谱关联。把原始内容变成"可被检索、可被关联"的知识单元。

**第三层：复用问题**
解决"存了 1000 篇但只读过 5 篇"。RAG 问答让你能问"我看过哪些关于 X 的内容"，学习路径帮你把散装内容组织成体系，周期回顾强制你重新触达。

---

架构上它的核心决策是：**用 pgvector 把关系型存储和向量存储合并在一个 PostgreSQL 里**，不引入独立向量库（Pinecone / Weaviate），这让整个系统只需要 4 个容器（Nginx + Next.js + FastAPI + PostgreSQL）就能跑起来，部署复杂度很低。

## 核心结论（讨论归纳）

### 用户定义的产品愿景

**一句话定义：** 以个人知识积累为基础，以 AI 辅助内容生产为核心，打造一套"第二大脑"工具。

### 核心价值链

```
采集（多平台、多模态）
  ↓
解析（结构化 + 语义索引 + 双链）
  ↓
创作（告知主题/受众/思路 → AI 生成初稿）
  ↓
编辑美化（AI 辅助编辑、插图、排版）
  ↓
定稿 → 发布（v2）
```

### 四大支柱

| # | 支柱 | 核心需求 |
|---|---|---|
| 1 | 多平台内容汇聚 | 低摩擦、一键式采集中文互联网碎片化内容 |
| 2 | 多模态内容解析 | 图文、视频、语音统一转化为可语义检索的知识单元 |
| 3 | 可视化展示 + 留痕 | 阅读时便捷批注，知识积累有迹可循 |
| 4 | AI 辅助内容生产 | 告知意图 → 初稿生成 → 人机协作编辑美化 |

### 最核心的痛点

写作心流被"找素材"打断——需要一个能在创作语境内直接提供知识支撑的系统，而非跳出去搜索。

### 与原项目的定位差异

| 维度 | inFlow AI 原项目 | 用户目标产品 |
|---|---|---|
| 核心终点 | 读完、记住 | 写出来、发出去 |
| 知识用途 | 个人消费 | 内容生产原料 |
| 创作支持 | 无 | 核心功能 |
| 编辑器 | 基础笔记 | 富文本 + AI 协作 |
