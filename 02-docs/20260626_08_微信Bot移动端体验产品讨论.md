## 一句话定义

让用户在微信 Bot 端，获得等同于 PC 端的内容反馈体验——从「入队确认」升级为「内容即时呈现 + 想法捕捉 + 随时分享」。

---

## 背景与起点

当前微信 Bot 的回执只有一句话：
> ✅ 已加入队列，解析完成后即可在 Trove 阅读：XXXX

用户在移动端缺乏即时反馈，且无法在「想法产生的当下」完成记录与消费。

---

## 用户核心场景

用户在闲暇时刻（健身、通勤、独处、户外）发现一个有价值的播客，但没有时间完整收听：

1. 扔给微信 Bot 做快速概读
2. 如果内容较浅 → 看一眼图片，转发分享，结束
3. 如果内容触动深度思考 → 想法转瞬即逝，需要即时捕捉，但此时不在 PC 旁

**核心痛点：想法丢失。** 不只是内容没看完，而是「在当前上下文下冒出来的想法，记下来也找不回当时的感受」。

## 移动端体验设计 · 三件事 + 一个兜底

解析完成后，微信 Bot 推送以下内容：

### 1. 播客精华卡（PNG 图片）
**目标：** 调动冲动脑，激发分享欲

包含元素（优先级排序）：
- 播客封面缩略图
- 节目名 + 期数/标题
- 3～5 条 AI 提炼要点
- 1 条金句
- Trove 品牌标 + slogan（传播时自带来源，类似「via Trove」）

技术路径：HTML 模板 + `playwright` 或 `html2image` 截图生成 PNG，AI 解析结果填入模板后自动渲染。

### 2. 语音摘要（TTS）
**目标：** 满足用户在健身、独处、户外等「耳朵空着」的场景下的音频消费

- 内容：AI 摘要的 TTS 播报（非原始音频剪辑，先闭环）
- 用户戴耳机边走边听，基础上下文建立后，脑子开始转

### 3. 随手记（想法捕捉）
**目标：** 捕捉转瞬即逝的想法，并与内容上下文自动绑定

- 用户直接回复 Bot 任何文字/语音
- Bot 自动关联到这期播客（不需要用户手动标注）
- PC 端打开后，想法与原文内容并排展示，可回溯

> **核心优势：** Bot 已知用户当前在消费哪期内容，这是其他笔记工具做不到的上下文自动绑定。

### 4. H5 链接（兜底）
**目标：** 用户想精读时，有地方去

- 现有 PC 端页面做好响应式即可，无需单独开发移动端
- 微信内直接打开，工作量最小

## 微信 Bot 的硬性限制

| 限制 | 影响 |
|------|------|
| 48小时消息窗口 | 无法主动推送，用户不发消息则断联 |
| 图片/音频大小限制 | 精华卡和语音摘要需控制体积 |
| 内置浏览器 API 受限 | H5 无法后台播放音频、无法发系统通知 |
| 无持久化界面 | 对话是线性的，不适合「笔记管理」 |
| 排版受限 | 所有内容依赖微信消息样式，无法自定义 |
| 内容合规风险 | 境外播客、敏感话题可能被过滤 |
