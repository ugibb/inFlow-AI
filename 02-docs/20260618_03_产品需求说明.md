# inFlow AI · 产品需求说明（PRD）

**版本：** v1.0（现状梳理）
**日期：** 2026-06-18
**项目：** inFlow AI — 面向中文互联网的稍后阅读 + AI 知识库

---

## 一、产品概述

### 1.1 产品定位

inFlow AI 是一款**可自部署的个人知识管理工具**，专为中文互联网用户设计。核心解决三个问题：

1. **采集问题** — 中文平台内容高度碎片化（微信公众号/抖音/B站/小红书），且存在反爬保护，难以统一入库
2. **理解问题** — 内容存入后缺乏结构化处理，无法被有效检索和关联
3. **复用问题** — 收藏了大量内容但真正重新触达的极少，知识沉淀效率低

### 1.2 核心价值主张

> 把"先存下，晚点看"重新变回"真的读完、真的记住"。

- **数据主权**：自部署，数据不上传给任何第三方平台
- **中文优先**：深度支持 8+ 中文平台（微信/抖音/小红书/B站/头条/掘金/CSDN/知乎）
- **AI 驱动**：每篇内容自动生成摘要、关键点、标签、向量嵌入、思维导图
- **轻量部署**：4 个容器（Nginx + Next.js + FastAPI + PostgreSQL），约需 4GB 内存

### 1.3 目标用户

| 用户类型 | 核心诉求 |
|---|---|
| 产品经理 / 研究者 | 收藏夹堆成山，真正读过的不到 5% |
| 工程师 / 终身学习者 | 希望收藏的内容最终能沉淀成体系 |
| 隐私敏感用户 | 不想阅读习惯被存在第三方服务器 |
| 被 Pocket/Omnivore 关停坑过的人 | 数据主权需求 |
| 内容策展者 | 需要结构化个人知识库 |
| 自部署爱好者 | 自己跑基础设施 |

## 二、应用场景

### 场景 1：一键收藏微信文章

**用户故事：** 作为一名产品经理，我在微信里看到一篇好文章，想存下来以后查阅。
**现有流程：** 转发链接给微信 Bot → Bot 自动抓取解析 → 5 秒内入库 + 自动生成摘要/标签 → 推荐相关文章
**痛点解决：** 微信没有官方 API，通过 ilinkai Bot 中转，绕过了平台限制

### 场景 2：多格式文件入库

**用户故事：** 我有一批 PDF 研究报告和 Word 文档，想统一整理到知识库。
**流程：** 拖拽上传 → MarkItDown 转换为 Markdown → AI 处理 → 可被搜索和关联
**支持格式：** PDF / DOCX / XLSX / PPTX / EPUB / CSV / TXT / HTML / MD

### 场景 3：语义搜索

**用户故事：** 我记得之前看过一篇关于"提示词工程"的文章，但不记得标题。
**流程：** 输入自然语言问题 → 向量化查询 → 余弦距离检索 Top-K 文章 → 列表展示
**效果：** 不需要精确关键词，语义相近的内容都能被找到

### 场景 4：RAG 知识问答

**用户故事：** 我想了解"我库里关于 React 性能优化的内容有哪些核心观点"。
**流程：** 提问 → 检索相关文章段落 → LLM 综合生成答案 → 附带引用来源
**效果：** 像有个助理帮你整理了所有相关笔记

### 场景 5：Spark 灵感创作

**用户故事：** 我有一个想法，想快速生成一篇结构化文章作为草稿。
**流程：** 输入一句话 → AI 规划结构（5 个部分）→ 逐节生成内容 → 保存为文章
**效果：** 快速从想法到可编辑的初稿

### 场景 6：知识图谱探索

**用户故事：** 我想看看我的知识库里哪些内容之间有关联。
**流程：** 进入图谱页面 → 可视化展示文章节点和语义关联边 → 点击节点跳转阅读
**效果：** 发现不同文章间的隐性关联，激发新思路

### 场景 7：定期知识回顾

**用户故事：** 我想每周收到一次提醒，复习一下最近入库的内容。
**流程：** 配置频率（如每 7 天）→ Bot 在指定时间推送 Markdown 格式摘要 → 点击跳转原文
**效果：** 强制触达沉睡内容，提升知识复用率

### 场景 8：Obsidian 备份

**用户故事：** 我想把知识库导出到本地 Obsidian，防止数据丢失。
**流程：** 生成同步 Token → Obsidian 插件拉取所有文章 → 保存为本地 Markdown
**效果：** 数据本地备份，哪天服务关了数据还在

## 三、功能模块清单

### 模块 1：内容采集

| 功能 | 描述 | 优先级 |
|---|---|---|
| URL 解析入库 | 粘贴 URL，自动抓取解析，支持 8+ 中文平台 | P0 |
| 批量 URL 导入 | 一次导入 1-20 个 URL | P1 |

## 四、非功能需求

### 性能
- 文章列表加载：< 500ms
- 语义搜索：< 1s（向量检索）
- AI 处理（摘要+标签+嵌入）：< 30s/篇（异步后台，不阻塞用户）

### 可用性
- 自部署 Docker 方案，最低配置：4GB RAM + 5GB 磁盘
- 支持无 GPU 运行（CPU 本地嵌入）

### 安全
- JWT 鉴权（24h 有效）
- 密码 bcrypt/Argon2 哈希存储
- 数据按用户严格隔离（ORM 层强制过滤）
- 图片反代防 SSRF：仅代理白名单域名

### 扩展性
- LLM 接入：任意 OpenAI 兼容厂商
- 嵌入模型：本地 fastembed 或外部 API 可切换
- 平台解析：新平台扩展只需在 parser_service.py 新增处理器

## 五、约束与边界

- **无浏览器扩展**（v1.0）：计划 v1.1 实现
- **无移动端 App**（v1.0）：计划 v1.1 实现 PWA
- **无批量重处理**（v1.0）：计划 v1.2 实现
- **无发布平台对接**（v1.0）：内容只在库内，不支持一键发布
- **微信 Bot 依赖 ilinkai**：需要企业微信开放平台账号
- **Obsidian 同步单向**：从 Trove 导出到本地，不支持从 Obsidian 回写（v1.0 只有 Obsidian → Trove 的上传接口，不自动同步本地修改）
