# 本地启动提示与微信 Bot 重绑提示优化方案

- **日期**：2026-08-18
- **状态**：已确认执行
- **背景**：本地服务访问提示不清晰 + 微信 bot 会话失效后无有效引导

---

## 一、问题诊断

### 1. 本地访问"不启动"的提示问题

- 前端启动日志被丢弃到 `/dev/null`（`start-local.sh` 第 487 行）——前端启动失败时用户**看不到任何原因**。
- `wait_for_services` 超时只给后端日志路径，没有前端日志，也没有常见原因诊断。

### 2. 微信 bot 重新绑定的提示问题

- **后端日志**：`_log_errcode` 只打印 `server errcode=-14 msg=session timeout`，用户看不懂、也不知道怎么办。
- **后端 `/status` 接口**：`hint` 措辞笼统，无法区分「刚绑定启动中」与「已失效 46 天」。
- **前端页面**：`WorkerNotReadyNotice` 只有「启动中」（蓝）和「未就绪」（琥珀）两种提示，失效账号显示成「已绑定 / 连接中」。

**数据库实测**（`wechat_accounts` 表，2026-08-18）：

| account_id | 状态 | 最后成功轮询 | 绑定时间 |
|---|---|---|---|
| `4abd8f345f5d@im.bot` | active | **2026-07-03**（46 天前） | 07-02 |
| `0c13516c71a8@im.bot` | active | **2026-07-02** | 07-02 |
| `9774ac850633@im.bot` | 已解绑 | — | — |

两个 active 账号的 `last_seen_at` 停在 7 月初，ilink 的 bot token 已过期（微信端掉线），服务端持续返回 `errcode=-14 session timeout`。因 `-14` 不在 bot.py 的失效码白名单 `(40001, 42001, 88001)` 内，bot 不会自动标记账号失效，只会无限重试 + 刷屏。

## 二、改动方案（4 个文件）

### 📋 改动 1 — `start-local.sh`：前端日志落盘 + 启动诊断增强

**现状痛点**：
- 前端启动日志被丢弃到 `/dev/null`，前端启动失败用户看不到任何原因。
- 启动超时只给后端日志路径，没有前端日志，也没诊断常见原因。

**改动**：
1. **前端日志落盘**：新增 `04-log/frontend/YYYY-MM-DD.log`，前端 `npm run dev` 输出重定向到该文件（不再丢弃）。
2. **重写 `wait_for_services`**：
   - 等待途中，后端/前端各自失败时，分别给出对应日志的 `tail -F` 指引。
   - 超时时：同时给出**前后端两份日志路径** + 针对性诊断（端口占用、node_modules 缺失、TypeScript 编译错误等）。
3. 启动完成提示里补充前端日志路径。
4. **成功启动日志落盘**：「系统启动完成」横幅（含访问地址、默认账号、日志路径）同时写入后端日志，`tail -F` 日志也能看到启动信息（修复「服务启动成功的日志未输出」）。

### 📋 改动 2 — `bot.py`：errcode 中文解读 + 节流修复 + 自动失效

**现状痛点**：`_log_errcode` 只打印 `server errcode=-14 msg=session timeout`，用户看不懂、更不知道怎么办。

**改动**：
- 新增 `ERRCODE_HINTS` 映射表：把 `-14 session timeout`、`40001/42001/88001` 等映射为中文。
- 首次遇到 `-14` 时提升为 **ERROR 级**并附操作指引：`微信登录会话已过期，请到「个人中心 → 微信绑定」解绑后重新扫码绑定`。
- 节流期间维持 WARNING 汇总，不刷屏。
- **修复节流 bug**：`_reset_errcode_log()` 原来在 HTTP 200 后就调用，导致 `-14`（body 报错但 HTTP 200）每次都被当作「首次」，每 5 秒刷一条。改为仅真正成功（errcode 为 0/None）时调用，节流才能生效（每 300s 汇总一次）。
- **日志带归属**：日志标注账号所属用户名，如 `[0c13516c71a8@im.bot (zhouzhiyi)]`，方便区分是哪个用户的账号报错。
- **-14 自动失效**：`-14 session timeout` 连续出现 ≥3 次（约 15s）判定会话失效，自动标记 `is_active=false` 并解绑（`unbound_at=now`），bot 不再无限重试；该用户重新扫码即可绑定。避免「已绑定但微信会话早已失效」的状态一直挂着。

### 📋 改动 3 — `router.py`：`/status` 接口增加 `connection_state` 分级

**现状痛点**：`/status` 的 `hint` 措辞笼统，前端无法区分「刚绑定启动中」和「已失效 46 天」。

**改动**：
- 新增结构化字段 `connection_state`：
  - `active`：心跳 < 2 分钟 → 正常。
  - `connecting`：刚绑定 / 心跳中断 < 10 分钟 → 等待重连。
  - `expired`：心跳中断 ≥ 10 分钟 或 绑定超 2 分钟仍无心跳 → **会话已失效**。
- `hint` 文案同步分级，expired 明确「请解绑后重新扫码绑定」。

### 📋 改动 4 — `WechatBinding.tsx`：页面三种状态提示

**现状痛点**：`WorkerNotReadyNotice` 只有「启动中」（蓝）和「未就绪」（琥珀）两种提示，失效账号显示成「已绑定 / 连接中」。

**改动**：
- 根据 `connection_state` 渲染三种状态：
  - `active` → 绿色「运行中」。
  - `connecting` → 蓝色「正在连接…」（保留现状）。
  - `expired` → **红色醒目提示**「⚠️ 微信连接已失效」+ 说明 + 一键「解绑并重新绑定」。
- `formatLastSeen` 超过 24 小时显示「X 天前」更醒目。

## 三、预期效果

- **本地启动失败**：终端直接看到前后端日志路径 + 常见原因诊断，不再瞎猜。
- **微信会话失效**：日志有中文指引，页面有红色「重新绑定」提示 + 快捷解绑按钮。
