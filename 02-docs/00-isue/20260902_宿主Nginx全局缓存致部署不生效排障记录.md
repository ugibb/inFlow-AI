# 宿主 Nginx 全局缓存致「部署了新前端却仍看到旧页面」排障记录

- **日期**：2026-09-02
- **状态**：已定位根因并固化修复（`proxy_cache off` 已生效）
- **涉及域名**：`inflow.huituai.site`（HTTP 80）
- **现象**：平台 tab + 动态统计接口部署后，后端路由 / 前端容器 / 本机 8080 均验证为新代码，但**公共域名仍返回旧版页面**，多次重启前端无效。

---

## 一、根因（一句话）

宝塔宿主 nginx 的 `/www/server/nginx/conf/proxy.conf` 末尾有一行 `proxy_cache cache_one;`，该文件被 include 进 nginx **`http{}` 顶层**。`proxy_cache` 是**可继承指令**，一旦写在全局 http 层，就会自动套用到**所有反代站点**（即使站点反代配置里一个字都没写 proxy_cache）。

于是宿主 nginx 把 `/library` 整页 HTML（引用旧版 JS chunk）缓存进磁盘 `/www/server/nginx/proxy_cache_dir`。前端容器怎么 rebuild / restart 都没用 —— 旧响应在**到达容器之前**就被 nginx 缓存层拦截直接返回。

**缓存 key 按完整 URL 记忆** → 这是本次排障的钥匙。

## 二、症状与判定特征（下次直接对号入座）

| 现象 | 说明 |
|---|---|
| 后端 `/openapi.json` 有新路由、前端容器 `.next` 有新字符串、`127.0.0.1:8080` 返回新页面，但**公共域名仍旧** | 病根在容器**之前**的缓存/转发层，不在代码 |
| **带 `?参数` 的 URL 是新页面，不带参数的是旧页面** | 🔑 铁证：某层按完整 URL 做的整页缓存（nginx proxy_cache / Next 缓存），参数一变即 cache miss 回源 |
| 响应头**看不到** `X-Cache: HIT` | ⚠️ **不要据此判定缓存未开启**。inflow 反代 conf 里 `add_header X-Cache` 与 `if{}` 块内的 `add_header Cache-Control` 混用，nginx 在 if 存在时不输出 X-Cache 头 |
| 宿主 nginx 缓存目录有体积 | `du -sh /www/server/nginx/proxy_cache_dir` > 0 即缓存确在发生 |

## 三、排障链路速查（从外到内，一次到位）

```bash
# 1. 看公共域名当前返回的页面 chunk（对比 git 里前端 build 后的新 hash）
curl -s http://inflow.huituai.site/<页面路径> | grep -oE 'page-[a-f0-9]{16}\.js' | sort -u

# 2. 关键分诊：带随机参数再测一次 —— 带参是新、无参是旧 = 整页缓存实锤
curl -s "http://inflow.huituai.site/<页面路径>?cb=$RANDOM" | grep -oE 'page-[a-f0-9]{16}\.js' | sort -u

# 3. 确认宿主 nginx 缓存是否在缓存 / 清空它
du -sh /www/server/nginx/proxy_cache_dir 2>/dev/null
rm -rf /www/server/nginx/proxy_cache_dir/* && nginx -s reload
```

**若清理后无参 URL 变新 → 缓存层即为元凶。**

## 四、固化修复（已完成，2026-09-02）

在 inflow 站点反代配置中显式关闭全局缓存的继承：

- 文件：`/www/server/panel/vhost/nginx/proxy/inflow.huituai.site/*.conf`
- 插入位置：`proxy_pass http://127.0.0.1:8080;` 之后一行，插入 `proxy_cache off;`
- 已 `nginx -s reload` 生效；**注意 `proxy_cache` 必须先于 if/add_header 等指令区域前声明无效时才需要用此法的 —— 本场景直接插入 location 顶部即可**

> ⚠️ **残留风险**：若日后在宝塔面板重新编辑/保存该站点的「反向代理」配置，可能重写此 conf，把 `proxy_cache off;` 冲掉。**定期自检**：
> ```bash
> grep -n proxy_cache /www/server/panel/vhost/nginx/proxy/inflow.huituai.site/*.conf
> # 必须看到 proxy_cache off; 若丢失则补回 + nginx -s reload
> ```

## 五、若服务器已新、用户浏览器仍旧的二次分诊

服务器 curl 无参已返回新页面，但用户仍看到旧 → **浏览器本地缓存**，与服务器无关：

1. 让用户**硬刷新**：macOS `Cmd+Shift+R` / Windows `Ctrl+Shift+R`。
2. 仍不行 → 用带参地址绕缓存：`http://inflow.huituai.site/<页面>?r=<日期>`（功能相同，仅绕缓存）。
3. 注意提醒用户确认地址栏是 `http` 还是 `https` —— 站点只配了 80，若是 `https://`（443）走的可能是另一套未更新的入口。

## 六、同类站点泛化提醒

`proxy_cache cache_one` 全局继承影响的是**同一台宿主 nginx 下所有反代站点**。若本机新增其它域名站点同样出现「改了没生效」，优先怀疑同一根因，直接对该站点反代 conf 加 `proxy_cache off;`，而不是去容器里反复重启。
